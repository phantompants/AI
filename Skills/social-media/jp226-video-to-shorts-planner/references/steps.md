Every step obeys the ground rules in SKILL.md: no invented dialogue, no unchecked visuals, say what could not be done, timing is provisional.

## Step 1: Build a searchable video map

**Needs:** the video or a timestamped transcript, plus the audience, problem, niche and goal.

**Produce** one table with these columns:

| Column | Notes |
|---|---|
| Source timestamp | HH:MM from the original video |
| Topic | A few words |
| Useful takeaway | What a viewer could do or understand afterwards |
| Demonstration or strong quote | Quote only what is actually said, word for word |
| Confidence | Clear, or the reason it is unclear |

**Checks**

- Use the original video's timestamps throughout.
- Flag unclear audio, and flag any section that could not be accessed.
- Do not describe on-screen action unless it was seen. For a transcript-only run, leave the demonstration column for quotes only.

## Step 2: Find the strongest clip candidates

**Needs:** the video map.

**Produce** up to 12 moments that could stand alone as [clip length] Shorts for [platform]. Return fewer if the footage does not support 12 strong ones. Say so plainly rather than padding.

Each candidate has:

- A permanent clip ID that will not change for the rest of the job, for example `C01`
- Source start and end
- The exact opening words and exact closing words
- The payoff, meaning what the viewer gets by the end
- Any missing context a viewer would need
- A rank, judged on opening strength, practical value and ability to stand alone

## Step 3: Choose seven distinct Shorts

**Needs:** the ranked candidates and the audience.

Pick seven for one week. Each must have a **different main takeaway**. Do not accept two clips that give the same advice with different hooks.

Where the footage supports it, mix quick wins, common mistakes, demonstrations and surprising insights.

**Return** per Short: original clip ID, working title, the viewer's problem, the takeaway, and why it was chosen. Flag any overlapping footage between picks.

If fewer than seven strong ideas exist, name the gap and suggest one specific pickup recording that would fill it, labelled `NEW RECORDING`.

## Step 4: Create hooks the footage can support

**Needs:** one clip ID at a time.

**Produce** three on-screen hooks, each under [8] words:

1. One built on a mistake
2. One built on a useful outcome
3. One built on curiosity

Each hook must match what the clip actually delivers. Then find the strongest **existing** spoken opening in the footage, quoting it exactly with its source timestamp.

Recommend one combination of on-screen hook and spoken opening. If a stronger spoken opening would need new recording, label it `NEW RECORDING` and keep it apart from the original dialogue.

## Step 5: Map every cut

**Needs:** the clip ID and the recommended hook.

Build a [30 to 45] second edit. Return **one row per retained segment**:

| Column | Notes |
|---|---|
| Segment | S1, S2 and so on |
| Original in / out | Timecode in the source video |
| New Short in / out | Starts at 00:00 |
| Retained dialogue | Exact words, no rewording |
| Edit instruction | What to do in the editor |

**Rules**

- Remove repeated points, unnecessary setup and distracting pauses. Keep the meaning and the natural delivery.
- Label every jump cut and every reordered section.
- Work out the total duration by adding up the retained segments, and show the sum.
- Mark uncertain boundaries for manual checking. Never imply frame accuracy.

## Step 6: Turn the cut map into captions

**Needs:** the latest cut map for the clip.

Produce SRT subtitle text for the **retained speech only**.

- Timing starts at 00:00 of the new Short, not the original video.
- Short phrase groups, two lines at most per caption, the speaker's own wording.
- Check the spellings of the names, tools and terms the user lists. Mark any word that is uncertain, separately from the caption text.
- Keep on-screen hooks out of the subtitle file.
- Label all timing provisional until it is checked against the assembled edit.

## Step 7: Plan the vertical crop

**Needs:** the cut map and the output size [1080 x 1920].

For each segment, state what must stay visible: face, hands, product, cursor or interface. Recommend one of three layouts, based on the actual footage:

- A single crop
- A split screen
- A full-screen insert

Describe placement in plain language, such as "face in the upper third". Keep captions clear of essential details and of the platform's own buttons. Flag any screen demonstration that becomes unreadable when cropped to 9:16.

If the footage has not been seen, give the plan as a set of questions to check in the editor rather than as findings.

## Step 8: Add visuals that explain the point

**Needs:** the edited timeline for the clip.

Suggest up to [4] useful additions. Each has:

- A timestamp on the edited timeline
- A duration
- The exact overlay text, under [6] words
- Its purpose

Prefer material that already exists: footage, screenshots, demonstrations. Label anything the user must create or source as `TO CREATE`. Use arrows, highlights or close-ups only where they clarify a specific step. Do not cover subtitles. Do not add decoration that competes with the lesson.

## Step 9: Map the audio edits

**Needs:** the edited timeline.

Look for audible hum, uneven speech volume, distracting breaths and abrupt audio joins. For each issue, give the timestamp and a plain-language fix in [editor].

- Keep natural breaths and the speaker's vocal tone.
- Apply the user's music preference. Where music helps, mark where it starts, where it fades, and where it drops beneath speech.
- Suggest sound effects only where they back up something visible on screen.

For a transcript-only run, audio cannot be heard. Say so and give a checklist for the user to run through, rather than listing found problems.

## Step 10: Review the actual rough cut

**Needs:** the uploaded rough cut, the source video and the latest cut map.

Check:

- The opening promises what the payoff delivers
- Cuts keep the meaning
- Captions match the speech
- Demonstrations stay readable
- The ending feels complete

**Return only actionable fixes**, each with: rough-cut timestamp, the problem seen, the exact correction, and a priority (high, medium or low).

Keep **confirmed** issues apart from **uncertain** ones. If a reference file is missing, list which checks could not be done.

## Step 11: Write the publishing copy

**Needs:** the finished clip.

Produce:

- Three titles under [55] characters
- Three cover-text options under [5] words
- One [platform] caption under [80] words

Target the audience, aimed at the specific problem. Draw on the clip's real takeaway, and work the chosen keyword in naturally. End with one relevant action (save, comment or follow).

Avoid unsupported results, fake urgency and "viral" promises. Finish by recommending which title and cover text work best together.

## Step 12: Package the full week

**Needs:** the latest version of all seven Shorts and the clip register.

Build a Monday to Sunday plan. Per day:

| Column | Notes |
|---|---|
| Day | Monday to Sunday |
| Clip ID | Permanent ID from Step 2 |
| Final title | From Step 11 |
| Viewer takeaway | One line |
| Duration | From the cut map total |
| Cover text | From Step 11 |
| Caption | From Step 11 |
| Filename | `[brand]_D01_[topic]`, with the day number counting up |
| Cut map and subtitle text | A clear label pointing to where each sits in this chat |
| Open fixes | Any unresolved items from Step 10 |

Suggest posting times only from analytics the user has supplied. With none, write "no data supplied" and leave the slot blank.

Before finishing, check that every row uses the latest cut map and captions. If something was changed after the last version was made, say which row is out of date.
